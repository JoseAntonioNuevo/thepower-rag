Review findings to address before live integrations:

1. Incorrect effective configuration in preflight.
scripts/preflight.ts:101 resolves APP_MODE only from process.env or Wrangler vars. It reads .dev.vars for variable presence but ignores APP_MODE in that file. In an isolated temporary copy, .dev.vars containing only APP_MODE=real was reported as effective demo and exited 0. This can give a false readiness result. Resolve the same configuration sources/precedence as the local Worker; do not combine independently present variable names into a configuration the Worker never receives. Add a regression test that does not use real credentials.

2. Stage changes retain the previous conversation.
apps/web/src/App.tsx:6 uses a module-global activeMode. Changing the stage clears the error but does not clear or isolate messages and does not prevent a change during streaming. Browser reproduction: send an offline response, select RAG, and the earlier no-RAG answer remains. It does not make the current foundation a fake RAG, but it would contaminate later comparisons and introduce races. Use component-local mode/transport state and a fresh conversation per mode/cohort/corpus selection. Abort and settle an active stream, or disable switches while busy.

3. Configuration needs to become capability-specific.
apps/api/src/env.ts and packages/contracts/src/limits.ts currently require EVALUATOR_MODEL_ID for all real mode requests. This matches the foundation's original policy, but the next phase must let a real no-RAG chat work without an evaluator or retrieval resources. Do not require future CRAG dependencies for basic capabilities.

4. Future secret filename coverage.
.gitignore ignores .dev.vars and .dev.vars.local, but not environment-specific names such as .dev.vars.production. Expand coverage to .dev.vars* before introducing such files. No actual exposed credential was found or read in this review.
