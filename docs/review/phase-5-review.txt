Confirmed issues to fix before real activation:

1. Final generation can overrun the advertised global deadline.
The graph checks time before starting generation, but accepts success after generation without checking that deadline again. An injected clock started at 0 and advanced to 21,000 ms inside generation. The 20,000-ms graph returned terminal=answer and accepted the late answer. No real delay or network call was used. Propagate one turn deadline through all adapters and reject late completion; separate provider cancellation limits from local waiting guarantees.

2. The returned ranking is validated but not applied.
rankAndAssess returned order [b,a], while usefulIds was [a,b]. Final generation received evidence [a,b]. The rank node stores the evidence decision but drops parsed.ranking. Apply a documented validated ordering to retained/final context and expose ranking scores/order in the trace. Membership/coverage evaluation alone is not observable reranking.

3. Duplicate discard summary keys.
Repeated retrieval of S16 appends duplicate discarded entries. App.tsx renders them with the same drop-<chunkId> key. Browser console confirmed React's duplicate-child-key errors. Deduplicate final summaries or use a unique per-attempt identity while preserving actual attempt history. The demo scenario selector also lacks disabled={busy}; align its behavior with the stage/cohort selectors so changing a script cannot clear an active stream.

4. Incorrect bibliographic attribution.
docs/crag-graph.md attributes arXiv:2401.15884 to Yan, Ding, Panda and Liu. The original source lists Shi-Qi Yan, Jia-Chen Gu, Yun Zhu and Zhen-Hua Ling. Fix the citation, keep the teaching adaptation distinction.
